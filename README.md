# Beacon War Room

Live event operations for Beacon Live: every department POC updates their checklist from their phone, the war room sees every department as green, amber or red, incidents are raised and closed with an audit trail, and each new event gets a compliance research run for its city.

Phase 1 of the spec. Show control (stages, run of show, artist check-in) is Phase 2.

## What's in the box

| Path | What it is |
| --- | --- |
| `supabase/migrations/0001_core.sql` | Tables, access rules (row-level security), functions |
| `supabase/migrations/0002_storage.sql` | Private photo-proof bucket and its access rules |
| `supabase/migrations/0003_seed.sql` | 26 departments and 154 default checklist items (generated by `scripts/build_seed.py`) |
| `api/invite.js` | Owner adds a person to an event (server function) |
| `api/compliance.js` | Compliance research run using the Claude API with web search |
| `src/` | The web app (installs to a phone home screen) |
| `tests/` | Access-rule tests and end-to-end browser tests |
| `scripts/localstack/` | Local test stack only. Never used in production |

## Setup (about 30 minutes)

### 1. Supabase

1. Create a project at supabase.com. Choose the Pro plan: free projects pause after a week without activity and have no backups.
2. **SQL Editor**: open each file in `supabase/migrations/` and run them in order: `0001_core.sql`, `0002_storage.sql`, `0003_seed.sql`.
3. **Authentication > Sign In / Providers > Email**: keep Email enabled. Turn **off** "Allow new users to sign up". Keep "Confirm email" on. Set Email OTP expiry to 3600 seconds.
4. **Authentication > Emails > SMTP Settings**: add your email provider (for example AWS SES, SendGrid, Resend). The built-in sender allows only 2 emails an hour, which is not enough for an event team. Then in **Authentication > Rate Limits**, raise "emails sent per hour" to at least 100.
5. **Authentication > Emails > Templates > Magic Link**: replace the body so it contains the 6-digit code. Suggested template:

   ```html
   <h2>Your Beacon War Room sign-in</h2>
   <p>Your code: <strong>{{ .Token }}</strong></p>
   <p>Or open this link on the same phone: <a href="{{ .ConfirmationURL }}">Sign in</a></p>
   <p>The code works for one hour.</p>
   ```

   Subject: `Your Beacon War Room sign-in code`
6. **Authentication > URL Configuration**: Site URL = your Vercel address (step 2). Add the same address to Redirect URLs.
7. **Create the owner account**: Authentication > Users > Add user > your email, tick "Auto confirm". Then in the SQL Editor run:

   ```sql
   update public.profiles set is_owner = true where email = 'you@yourdomain.com';
   ```
8. **Project Settings > API**: copy the Project URL, the anon (publishable) key and the service_role (secret) key for step 2.

### 2. Vercel

1. Import the GitHub repo `thelastradio/beaconwarroom`. Framework: Vite (detected).
2. **Settings > Environment Variables** (Production and Preview):

   | Name | Value |
   | --- | --- |
   | `VITE_SUPABASE_URL` | Supabase Project URL |
   | `VITE_SUPABASE_ANON_KEY` | anon / publishable key |
   | `SUPABASE_URL` | Supabase Project URL |
   | `SUPABASE_ANON_KEY` | anon / publishable key |
   | `SUPABASE_SERVICE_ROLE_KEY` | service_role / secret key. Server only, never share |
   | `SITE_URL` | your Vercel address, e.g. `https://beaconwarroom.vercel.app` |
   | `ANTHROPIC_API_KEY` | Claude API key (step 3) |
   | `ANTHROPIC_MODEL` | optional, defaults to `claude-sonnet-5-5` |
3. Deploy. Put the final address into Supabase Site URL (step 1.6) if it changed.

### 3. Claude API (compliance research)

1. console.anthropic.com > API Keys > create a key named "Beacon War Room". Paste it into Vercel as `ANTHROPIC_API_KEY`.
2. Settings > Limits: set a monthly spend limit. Web search costs US$10 per 1,000 searches plus model tokens; a new event typically uses up to about 84 searches (14 categories, up to 6 each); the app shows the searches and estimated cost of every run.

### 4. First run checklist

1. Open the app, sign in with your owner email and the emailed code.
2. Create a test event. Compliance research starts automatically; each category takes up to a minute.
3. On **People**, add a second email of yours as a POC. Sign in with it on your phone, add the app to the home screen, and update an item with a photo.
4. Check the **War room** on a laptop updates within a few seconds ("Live" in the top bar). If it says "Synced … ago" instead, check Database > Publications > `supabase_realtime` includes `items`, `incidents`, `broadcasts`.
5. Put the phone in airplane mode, update an item, turn signal back on: it sends by itself.

## Who can do what

| Role | Sees | Can change |
| --- | --- | --- |
| Owner | All events | Everything, including people and access |
| Event Controller | One event, all departments | Any item, incidents, broadcasts |
| Department POC | One event, all items read-only, own department editable | Own department's items; raise incidents; close L2–L4 in own department |
| Viewer | One event | Nothing |

Rules are enforced by the database, not just hidden buttons. Status changes are only possible through the update history, so nothing is overwritten.

## Editing the default checklist

Edit `scripts/build_seed.py`, run `python3 scripts/build_seed.py`, then in the Supabase SQL Editor run:

```sql
delete from public.template_items;
```

followed by the new `0003_seed.sql`. Only events created afterwards use the new list.

## Tests

- `python3 tests/rls_test.py` — 55 access-rule checks against a local Postgres with the migrations applied.
- `python3 tests/e2e.py` — 38 end-to-end checks in a real browser: email-code sign-in, event creation, compliance research (mocked research service), invites, POC phone updates with photos, offline queue, incidents, broadcasts, viewer read-only, access removal, research reuse.

Local stack: Postgres 16, Supabase Auth and PostgREST binaries, `scripts/localstack/gateway.mjs` (stands in for Supabase's gateway, storage and the Vercel functions).

Not testable locally, verify on the real project: live push updates (Supabase Realtime), storage access rules, and real Claude web-search results.
